•	What is bean?
o	Beans = object/POJO that instantiated, configured, and managed by the Spring IoC container
o	Spring container manages the lifecycle of the beans
•	Bean lifecycle
o	refers to the stages a Spring-managed bean goes through from its creation to its destruction
o	Instantiation: Object is created.
o	Dependency Injection: Properties are injected.
o	Aware interfaces: Bean receives Spring-related information (e.g., name, factory).
o	Pre-Initialization: BeanPostProcessors before initialization logic.
o	Initialization: Bean is initialized (via @PostConstruct, InitializingBean, or initMethod).
o	Post-Initialization: BeanPostProcessors after initialization logic.
o	Bean Ready: Bean is ready for use.
o	Destruction: Bean is destroyed (via @PreDestroy, DisposableBean, or destroyMethod).
•	what is the use of beans?
o	Dependency Injection: Automatically injecting dependencies between components.
o	Inversion of Control (IoC): Spring manages the lifecycle and configuration of objects.
o	Business Logic Encapsulation: Beans represent core application components.
o	Singleton/Prototype Scope: Efficiently managing object creation based on need.
o	Configuration Management: Beans are used to define and configure the application.
o	Cross-Cutting Concerns: Managing transactions, security, logging via AOP.
o	Lifecycle Management: Handling initialization and cleanup operations.
o	Testability: Supporting modular and easily testable code.
o	AOP Support: Applying cross-cutting concerns like logging and security.
•	How to register beans
o	XML Configuration: Suitable for legacy applications but less common in modern Spring applications.
o	Java-Based Configuration: Preferred for type safety and better refactoring support.
o	Component Scanning: Simplifies bean registration by automatically detecting annotated classes.
o	Dependency Injection: Use @Autowired to wire dependencies.
o	Multiple Configurations: Use @Import to manage multiple configuration classes.
•	Bean scopes
o	It defines how the Spring container manages the lifecycle and the instances of a bean
o	Several scopes in Spring:

_______________________________________________________________________________

Scope	Description	Lifecycle
Singleton	Single instance per Spring container (default).	Created when the container starts, destroyed when it shuts down.
Prototype	New instance for each request.	Created and discarded after each request.
Request	Single instance per HTTP request.	Created and destroyed with each HTTP request.
Session	Single instance per HTTP session.	Created and destroyed with the HTTP session.
GlobalSession	Single instance per global HTTP session (used in portlets).	Created and destroyed with the global session.
Application	Single instance per ServletContext (used in web applications).	Exists for the entire lifecycle of the ServletContext.

Lifecycle	Created for each HTTP request; destroyed after the request	Created every time it is requested; not managed by the container post-creation

•	What is RestTemplate, WebClient in detail?
o	Use RestTemplate:
	For simple, blocking applications that require minimal HTTP interaction.
	If you do not need reactive programming.
o	Use WebClient:
	For applications that require reactive programming and high concurrency.
	When you need non-blocking I/O and support for streaming.
o	Use OpenFeign:
	When you want a declarative way to create HTTP clients with minimal boilerplate.
	If you are already using Spring Cloud and need service discovery and load balancing features.
o	Comparison of RestTemplate, WebClient, and OpenFeign
Feature	RestTemplate	WebClient	OpenFeign
Synchronous/Asynchronous	Synchronous	Asynchronous (supports both)	Synchronous
Usage Context	Simple applications	Reactive applications	Declarative HTTP clients
Error Handling	Built-in error handling	More control over error handling	Customizable error handling
Streaming Support	Limited streaming support	Full support for streaming	Limited, depending on the underlying HTTP client
Configuration	Manual configuration	Fluent API	Declarative interface
Complexity	Simple and straightforward	More complex, but powerful	Reduces boilerplate code

•	Dependency injection
o	Dependency Injection (DI) is a design pattern used to achieve loose coupling by injecting required dependencies from outside the class rather than creating them internally.
o	There are three main types of DI: constructor injection, setter injection, and field injection.
o	Spring is a popular framework that uses DI to manage dependencies among classes and their lifecycle.
o	DI improves testability, maintainability, and reusability of code while promoting separation of concerns.
•	IOC
o	Inversion of Control (IoC) is a design principle where the control of creating and managing dependencies is inverted to an external container, allowing for more modular, testable, and loosely coupled code.
o	Spring uses IoC to manage beans (objects) and inject dependencies through Dependency Injection (DI).
o	IoC improves maintainability, testability, and reusability of code by decoupling dependencies from classes.
•	Difference Between IoC and Dependency Injection
o	IoC is a general concept, where the control of how objects are created and how they depend on each other is inverted from the objects themselves to an external container or framework.
o	Dependency Injection is a specific technique used to achieve IoC by injecting dependencies into objects, either through constructor injection, setter injection, or field injection.
